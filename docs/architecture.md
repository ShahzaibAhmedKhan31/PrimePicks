# Architecture and packaging notes

## Runtime architecture

- Electron is the Windows desktop shell and lifecycle owner. It selects a free loopback port, starts the bundled backend, waits for `/api/health`, and opens the local UI. On application shutdown it requests a token-protected backend shutdown so extraction tasks and the visible Playwright context close cleanly.
- FastAPI serves the bundled React build in the installer and exposes a local JSON API. Developer mode uses Vite and proxies API requests to port 8765.
- Playwright launches **headed** Chromium with a persistent per-user profile. Verification is detected, then extraction waits for an explicit user Continue action. No CAPTCHA-solving, stealth, or browser-fingerprint workaround is used.
- BeautifulSoup parses the rendered page HTML into a Pydantic product snapshot. Extraction is deliberately heuristic and preserves a missing-information list for user review.
- OpenAI receives the extracted snapshot and a system prompt requiring a strict JSON schema. The response is Pydantic-validated before it reaches the editor. No HTML is generated by the AI.
- Jinja2 renders `backend/app/templates/listing.html` independently. Jinja autoescaping is enabled; generated descriptions and labels are escaped. The template uses inline styles, tables, and no JavaScript or external stylesheets.
- SQLite stores history and model preferences. The OpenAI key is written to the Windows credential vault when available; a Fernet-encrypted file fallback supports developer machines without an OS keyring.

## Data and privacy boundaries

- The UI talks to the local backend via relative `/api` paths. Packaged Electron binds the backend to loopback, not to a public network interface.
- The user's product data is sent to OpenAI only when the user generates listing copy. The application has no hosted account or shared API credential.
- Product image URLs are preserved as remote URLs and included only when selected. The app does not upload, download, or host product images.
- Listing database and Chromium profile data are stored under the per-user application-data directory. `PRIMEPICK_DATA_DIR` can override this for local development/testing.

## Windows package assembly

`scripts/build_windows.ps1` assembles these artifacts:

1. Vite static assets in `frontend_dist/`.
2. Python environment and backend dependencies (PyInstaller onedir output).
3. Playwright Chromium binaries installed to `desktop/resources/playwright-browsers/`.
4. Electron NSIS setup artifact in `desktop/dist/`.

The setup includes the backend executable, its PyInstaller runtime files, browser binaries, Electron, and static frontend assets. It does not include an OpenAI API key. Build on Windows x64 to ensure the embedded Python executable and native packages target Windows. The installer is currently unsigned; add a signing certificate to the electron-builder configuration for production distribution.

## Known constraints

AliExpress DOM, page access, region, and verification behavior are outside the app's control. The extractor uses visible page content and common title/description/specification/gallery selectors. For pages that don't expose product details normally, it stops or returns explicit review notes rather than attempting access workarounds. eBay may sanitize HTML and can change listing-description rules; check final pasted HTML on eBay before publishing.
